# Findings — #1710 live-PR message-pattern preflight

## The fleet handover path does not call the live-PR preflight, so the seam is still advisory in practice

- **Signature:** fleet-handover-does-not-call-live-pr-preflight
- **Evidence:** `make pr-message-check PR=<n>` now exists and is proved by
  `tests/test_pr_message.py::test_the_live_pr_preflight_refuses_a_body_the_check_rejects`
  (stub gh: good body 0, bad body 1, failed read 2, both through make). But no `tll-*/SOUL.md`
  or lane skill names `make pr-message-check PR=<n>` in its handover step; §7b still only asks
  lanes to run the file-form check. A lane can therefore hand over a branch whose live body
  the new seam would refuse — the merge-time hold (#1704) still catches it, but the authoring
  class #1710 exists to remove.
- **Why:** a mechanical seam nobody calls is no more binding than the advisory instruction it
  replaces; the class recurs as held PRs and human nudges.
- **Done when:** the reviewer/watcher handover step in the fleet lane skills calls
  `make pr-message-check PR=<n>` and refuses to hand over on a non-zero verdict, with a guard
  in `tests/test_fleet_lifecycle.py` that fails on the current tree and passes on the fixed
  one; filed as its own `tech-debt` issue handed to `tll-planner`, not fixed in this change.
