# Findings — #1699 gateway-error outage classification

## The timeout prong is stricter than the error-page prong, so one non-gateway transport error still flips an outage to `quiet`

- **Evidence:** measured on this change's head (`scripts/update_trending.py::zero_hit_verdict`, driven directly):
  - `34 × "The read operation timed out" + 1 × "Connection refused"` → `timeouts=34`, verdict **`quiet`** (exit 1).
  - `23 × target error page (outage=23) + 1 × failed` → verdict **`outage`** (exit 0) — the #296 rule that a `failed` query "proves nothing about the mirror either way".
  The timeout prong requires `timeouts + outage == queries`, while the error-page prong only requires `queries and outage and not with_hits and not answered`. Same shape, opposite verdicts — the exact class #1699 measured for `HTTP 502`, still live for every transport error outside the gateway family (`Connection refused`, DNS, TLS).
- **Why:** issue #296 states the intended rule — an unclassifiable transport failure must never disqualify a proven unreachable-mirror verdict, because it is not evidence the mirror is healthy. The timeout prong contradicts it, so a dead mirror reached through a mix of timeouts and one connection-level error is reported as a QUIET SEARCH and reds `live-smoke` on every open PR.
- **Done when:** the two prongs apply the SAME discriminator — a `failed` query neither excuses nor condemns, so `N` recognised transport failures (timeout or gateway family) out of `queries` with no answered query, no hit and no refusal verdict `outage`/exit 0, with a RED-first test pairing the timeout shape against the error-page shape above.
