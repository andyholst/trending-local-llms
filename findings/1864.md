# Findings

## DGX Spark rows that name no NVIDIA/CUDA token still classify Metal

- **Evidence:** real-store probe on base `805a741f7a6cc61c5b8704d7894ed760a9f1348b` (120 models, 50 engines): the 13 explicit-token rows misclassified as Metal are fixed, but `qwen3.8-flash-next-125b | DGX Spark | 67 t/s` and `glm-5.3-flash | 2x DGX Spark (200 Gb/s link) | 109.1 t/s` carry no `rtx` / `nvidia` / `cuda` / `geforce` / `tesla` / `a100` / `h100` / `l40` / `aic` token, so `measurement_backend()` still classifies them through the TensorFold/MLX Metal registry. `_CUDA_HW` also does not contain `dgx` or `gb10`.
- **Why:** the issue scoped the fix to explicit NVIDIA/CUDA tokens, so adding a bare product-name token here would be an unasked-for classification change and would risk matching hardware text where a vendor-neutral product name is used. These rows remain visible in the Metal table even though the hardware is an NVIDIA DGX Spark.
- **Done when:** a triaged change either declares `dgx` / `gb10` as explicit NVIDIA hardware with a real-file guard covering both rows, or records the rows as a data-only decision to keep them in Metal; until then the classification is unchanged and the finding stays open.
