# Findings

## The duplicate gate and ingest used two different justification sources

- **Evidence:** `validate.py:1662-1671` (base) justified a cross-row duplicate only from `measurement_model_aliases`, while `update_trending.py:3075-3077` accepts the same tuple on `CROSS_MODEL_ALLOW_LIST` match. Removing the two allow-list-exact aliases at `update_trending.py:2732-2734` and `2750-2753` in memory produced exactly two `validate --only data` failures (vLLM 25.4 / GuideboardLabs and llama.cpp fork 21 / laky_fx). Guard `tests/test_engine_figure_alignment.py::test_allow_list_exact_pairs_are_justified_without_an_alias` fails 2 checks on the fetched base and passes on this PR's head.
- **Why:** an implementer following #1213's original "migrate to the allow-list, then remove the alias" sequence lands a red PR precisely for the two pairs that look safest to migrate, because the read path never learned the write path's justification.
- **Done when:** the gate consults the same allow-list with the same identity key, and an allow-list-exact pair with no alias stays green in both the guard and the shipped store. Landed in this PR.

## A stated-but-unparseable counterpart was granted an alias silently

- **Evidence:** `update_trending.py:3816-3837` (base) returned None from `cross_identity_alias_reason` whenever either `params_identity` missed; four shipped models state such values (`gemma-4-e4b` "E4B", `deepseek-v4.1-flash` "MoE", `laya-mlx-decision-models` "421M / 322M", `laguna-xs-2-1` "MoE, ~3B active"). Planting `measurement_model_aliases:['gemma-4-e4b']` on the 27B row added it at ingest with a REFUSED count of zero and no REPORT line. Guard `tests/test_alias_identity_gate.py::test_unparseable_params_alias_is_refused_at_ingest_and_reported` fails 5 checks on the fetched base and passes on this PR's head.
- **Why:** the visible cross-identity ledger still read 12, so a new attribution of one model's t/s to another through the exception path was invisible to the reviewer while the gate stayed green.
- **Done when:** ingest refuses and names the counterpart, the store gate reports it, and genuinely absent params keep the documented #1207 fail-open so existing same-family captures stay legal. Landed in this PR.
