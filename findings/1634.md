# Findings — issue #1634 (repair C: drift-triggered index keeper)

Analysis of what this landing touched (rule 6g). Two items; neither is fixed inside
this change.

## Residual: pre-squash index regeneration still covers only behind-and-clean BOT heads

- **Evidence:** `scripts/auto_merge_rebase.py:73-92` (`classify`) regenerates
  `OPENSPEC.md` only on the `behind-and-clean-bot` verdict; the design measured 16 of
  the 25 most recent merged PRs authored by `andyholst` (human-owned ⇒ report-only),
  and the #1625 instance itself came from PR #1617, authored by `andyholst`.
- **Why:** a CURRENT bot head whose committed index predates concurrent archives still
  squashes drift, and ~64% of merges are human-owned and never rewritten (§6s/#1089
  refuses rewriting a human's branch). Repair C bounds the rot — the keeper fixes
  master minutes after the push — but does not prevent it at the squash.
- **Done when:** a separate small change extends the pre-squash regeneration to the
  `current` bot verdict (and answers the human-owned question). Named out of scope by
  the `BOT tll-architect · design #1634` comment; handed to `tll-planner`.

## Deviation: `--drift` exits 2 where `--check` exits 1 on a missing/unreadable index

- **Evidence:** `scripts/openspec_index.py` (`main`): the missing-file branch returns
  `2 if a.drift else 1`, and the new `read_text` guard returns `2 if a.drift else 1`;
  `tests/test_openspec_index_drift.py::test_a_missing_index_is_loud_in_the_report_mode`
  pins both numbers.
- **Why:** the dispatch specified exit 2 for the REPORT mode ("a report that cannot be
  produced"), while `--check`'s contract is unchanged. The two modes therefore spell
  the same failure with different codes; recorded rather than silently unified, because
  changing `--check`'s code would alter a pinned gate.
- **Done when:** either a ruling that both modes share one code, or this note stays as
  the declared deviation. No action required for #1634 to land.
