## The lane-side pre-push message check is advisory, so a body its own check refuses still reaches auto-merge

- **Signature:** lane-pre-push-body-check-advisory
- **Evidence:** §7b requires a lane to run `python3 scripts/pr_body.py --check-body-file <f> --branch <b>`
  before a push, but nothing makes it binding. PR #1696's squash landed on master as `8184e59d`
  with the authored body verbatim, and that exact body is refused offline:
  `python3 scripts/pr_body.py --check-body-file body.md --branch fix/owed-row-prose-quotes-1690`
  → `[pr-message-check] REFUSED: … missing required section(s): ## Why, ## What, ## How, ## Benefits, ## Technical Solution`
  (exit 1). This change closes the MERGE path (#1704); the authoring path still relies on a lane
  remembering a §7b instruction.
- **Why:** the hold turns a silent bad landing into a held PR, which is correct but costs a full CI
  round and a human nudge for every occurrence; a lane that never runs the check keeps producing
  them. A mechanical pre-push refusal removes the class instead of catching it downstream.
- **Done when:** the fast offline body check is reachable from a lane's own push path (a pre-push
  seam or a watcher/verdict rule that refuses to claim a branch whose body fails it), proven RED on
  the current tree and green after, with no new LLM call and no workflow change.
