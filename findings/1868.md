# Findings — issue #1868 (additive DGX-Spark hardware clarification)

## Raw snapshots still carry the contradictory AMD-APU-plus-GB10 hardware string

- **Evidence:** The two clarified rows in `data/measurements.json` now name the NVIDIA DGX Spark (GB10) in an appended parenthetical, but the raw captures that produced them (`data/raw/amd-20261019-180230.json`, `data/raw/metal-20261024-195508.json` and siblings) still carry the bare `Radeon 8060S / Strix Halo 128GB (ASUS Ascent GX10, GB10)` value. This delivery is scoped to the shipped store only — `data/raw/*.json` is history and was deliberately not touched.
- **Why:** Any future re-ingest from those raw snapshots could reintroduce the ambiguous string into the store, losing the reader-visible clarification this change just added. The history is immutable here, so the risk is deferred rather than removed.
- **Done when:** A separately dispatched, owner-ruled change decides whether raw history may be annotated or whether ingest should carry an additive clarification forward, with a real-file guard proving the reader-visible value survives a re-ingest. This lane does not edit raw history or apply a `tech-debt` / `data-gap-analysis` label.

## PR #1867's guard keyed delta rows by the exact hardware string

- **Evidence:** On head `3c00bf44` plus the #1868 append, `python3 tests/test_dgx_gb10_cuda.py` reported `PASSED 31 | FAILED 2`: the two failures were `delta row present: qwen3.6-35b-a3b / … / 87.2` and `… / 188.9`. The `#1866` delta ledger in `findings/1866.md` records the pre-clarification hardware string and `rows_by_key()` used it as an exact match key. Classification itself never regressed — both rows still return `CUDA`.
- **Why:** An additive, rule-3b-compliant data clarification broke a test that treated a mutable string as an identity key. Keeping that guard green is an explicit acceptance criterion of #1868, so the lookup (not the classification assertions) was made tolerant of an additive suffix in this delivery; the six-row enumeration and every backend assertion are unchanged.
- **Done when:** The guard is green on head (`PASSED 37 | FAILED 0`) with its classification assertions intact, and a future review can confirm the tolerance helper matches only prefix-related rows for the same model/engine/tps — never a different measurement.
