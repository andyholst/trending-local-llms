## The coverage report still counts queries the prompts no longer append

- **Evidence:** measured on this branch with a synthetic store of two trending rows — one `id: "named-model"`, one `id: ""` (`scripts/query_coverage.py`): the default report prints `2 derived (throughput) + 2 footprint ... added to EACH leg = 51 sent in total`, while `--queries` emits only `named-model tokens per second,named-model vram ram context weights offload engine version` (35 curated + 2 = 37 per leg). Before #1688 the two agreed, because `prompt_queries()` returned the raw composition unchanged.
- **Why:** `report()` reads `UT.all_search_queries()` / `UT.derived_queries()` / `UT.footprint_queries()` directly, so its derived/footprint/aged counts and its "sent in total" line still include the vacuous empty-id queries that `prompt_queries()` now drops. A reader trusting the report overestimates what each search leg actually sends.
- **Done when:** the report's derived/footprint/aged counts and the "sent in total" line are computed through the same filtered seam as `--queries` (or explicitly labelled as the pre-filter composition), with a test pinning report/`--queries` agreement on a store that carries an unnamed ranked row.
