# Findings

## The reconcile seam never compared the host rulebook, so a stale AGENTS.md stayed green

- **Evidence:** RED-first on fresh base `d0f5dc5840e86db1a331734480397abebb3447ae`: `tests/test_fleet_host_reconcile.py` printed `FAIL attended WRITE=1 repairs a stale host`, `FAIL the host AGENTS.md is classified STALE against the fetched base`, `FAIL an unattended protected write exits 2` and `RED_RC=11` against the unmodified source (`MIRROR_RELS` covered only `SOUL.md` + `skills/<lane>/SKILL.md`). After the fix the same module is `GUARD_RC=0` with all four new scenarios plus the wiring guard green, and `make fleet-host-reconcile BASE=HEAD PROFILES_HOME=agents RULEBOOK=AGENTS.md` prints `OK: base d0f5dc..., 8 lane(s), every text mirror matches` with `CI_RC=0`.
- **Why:** `fleet_host_sync_check.py` refuses host drift but names no direction; `qa-validate.yml` ran the reconcile seam report-only. With the rulebook outside the comparison set, a machine could hold a stale `AGENTS.md` (the canonical collaboration / cadence rules) while every gate stayed green — the host could not self-correct. The repo-root rulebook is authoritative for the fleet, so its host copy belongs in the same one comparison set.
- **Done when:** an attended host run lands the lossless union with `WRITE=1 ATTESTED=1` and a timestamped backup, a stale host rulebook converges to the repo bytes, a forward host note survives, and an unattended protected write refuses before touching any file. CI stays read-only and no runtime stamp or `config.yaml` byte is written.
