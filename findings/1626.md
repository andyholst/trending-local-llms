# Findings

## The live-run authority limit is enforced as a doubled bound only — the "still LIVE" exemption (#1265 §3B) is not implemented

- **Evidence:** `scripts/stale_claim_sweep.py` picks the bound pair from `is_run_bearing(newest.body)` alone (the claim text carries `R:<id>` or `PR #<n>`); no path in the seam calls `gh run view <id> --json status` or reads the PR state, so a claim whose run has CONCLUDED, or whose PR has MERGED, still gets the doubled 180/360 pair. `#1265` §3B specifies that a run still `in_progress`/`queued`, or an open PR whose newest run is not concluded, is EXEMPT from sweeping altogether ("A live run is EXPLICITLY exempt: voiding it would tell a second lane to push to a branch while CI is reading it").
- **Why:** the design's distinction — a LIVE run is never swept, concluded evidence earns only the doubled grace — is not observable in the seam, so the sweeper can neither protect a branch CI is actively reading nor shorten the grace of a finished run; the pinned rule is weaker than the design it cites.
- **Done when:** the thin `gh` layer resolves each run id / PR number the decision sees and `sweep_thread` emits nothing for a still-live run while keeping the doubled pair for concluded evidence — locked by a test with a stubbed `gh run view`/PR read proving both directions (RED on this head).
