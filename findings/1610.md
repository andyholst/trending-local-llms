# Findings

## The live sweep reads open issues N+1 and silently truncates at `--limit`

- **Signature:** stale-claim-sweep-live-read-bound
- **Evidence:** `scripts/stale_claim_sweep.py::fetch_open_threads` runs one `gh issue view --json number,state,comments` per number returned by `gh issue list --limit $(--limit)` (default 200). Measured on the live board 2026-11-24T15:05Z: 125 open threads walked, 71 carrying comments, ~2 s end to end. A thread past the cap is never read and produces no line, with nothing in the output naming the truncation.
- **Why:** the seam's contract is that silence means "no claim crossed a bound". An issue beyond the cap therefore reads as "not stale" when it was simply never looked at — the same partial-report-as-clean defect the seam exists to remove, and the exact shape rule 6d/§8 call a vacuous green.
- **Done when:** a follow-up change either paginates past the cap or emits a loud `[stale-claim-sweep] truncated at N open issue(s)` line so an incomplete read can never be mistaken for a clean verdict. Child 4's writing half (the PING/RELEASE consumer) should read the bound too.
