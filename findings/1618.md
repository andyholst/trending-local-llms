# Findings

## A host-only config setting is deleted by the very re-provision that syncs the skill mirrors

- **Signature:** fleet-host-sync-declared-lane-append
- **Evidence:** at origin/master `1418925c` on asimov@mac, `make fleet-host-sync-check BASE=origin/master` reported 6 divergences: five lane SKILL.md files plus `tll-implementer/config.yaml: fallback_providers: drifted from the rendered chain`. The host config carried the owner-authorized #1591 `security.protected_instruction_files: false`; `agents/tll-implementer/config.yaml` did not. `agent_profile_provision.provision_one` copies whole bytes from the rendered chain, so provisioning that lane would delete the setting, while `agent_model_chain.config_problems` refuses a hand-added block.
- **Why:** the sync gate compares OWNED blocks against the fetched base while provisioning copies whole rendered bytes, so a legitimate host-only profile setting has no representable home in the tree: it either reds the gate or is erased by the fix. Five skill mirrors had the mirror-image problem — legitimate lessons had no landing path and host rewrites had silently dropped master's canonical bullets.
- **Done when:** a lane can declare an extra config block in the tree, the renderer emits it after the byte-exact chain, provisioning preserves it, an undeclared extra still reds, and all six divergences reconcile to zero without discarding a lesson.
