## The arm64 smoke fails on an amd64 runner with no declared binfmt handler

- **Evidence:** On the fetched base `90f81d4d1234fdd1e9e6c84b0aa38dbb89532fd8`, `.github/workflows/refresh-bot.yml:276-283` runs `docker run --rm --platform linux/arm64 <tag> hermes --version` in the `build` job, but no `docker/setup-qemu-action` step exists anywhere in `.github/workflows/`. RED-first on this host (`uname -m` = aarch64, no binfmt_misc, image `dockerfile-2580f8a3eedf` already local): `docker run --rm --platform linux/amd64 … hermes --version` -> `exec /root/.local/bin/hermes: exec format error`, **rc 255** — byte-identical to refresh run 45609673982. Native `--platform linux/arm64` control -> `Hermes Agent v0.23.4 (2026.9.24)`, rc 0, proving the layer is sound (the designer scanned 581 AArch64 ELFs, zero x86-64). The new guards RED on the base tree and GREEN on the head.
- **Why:** rule 6d forbids a second arch-selection contract, but a runner-side emulation prerequisite is not an arch choice: buildx's own arm64 build emulation does not register a host binfmt handler for the later plain `docker run`. The old comment claiming it did was false, so the prerequisite was never declared.
- **Done when:** the `build` job registers a 40-hex-pinned `docker/setup-qemu-action` with `platforms: linux/arm64` immediately before the smoke; the smoke execs the arm64 child and reads `/opt/hermes-version.txt`; `image_manifest_check.REQUIRED_PLATFORMS` stays the single publish-platform set; and the live amd64 runner's smoke goes green (this host cannot mount binfmt_misc, so the GREEN-with-handler is CI evidence only, not a locally fabricated result).
