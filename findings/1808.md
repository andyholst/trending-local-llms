# Findings

## scrubbed_run accepts a zero-line stream from a successful producer while #1747 says a silent agent must fail

- **Evidence:** measured on this branch with the REAL `scrubbed_run` seam and a stand-in Docker CLI: a producer that sleeps and prints nothing (`make quiet` in `tests/test_scrubbed_run_seam.py::_stream_fixture`) exits 0 and the redactor prints `[scrub-log] stream: 0 line(s)` with no `[agent]` line and no failure. The `#1808` issue body (and the seam's `#1747` classification text) states the anti-vacuous contract as "a genuinely silent agent must still FAIL — do not turn it into a skip or retry-all", yet the seam only classifies SIGPIPE (141); a producer that exits 0 with an empty stream is green.`
- **Why:** an agent that starts, produces nothing and exits 0 is exactly the quiet/agent-failed shape #1747 set out to catch; leaving it green means a refresh search leg that silently produced no posts still looks like a successful leg, and the store silently stops updating.
- **Done when:** either the seam refuses a zero-line stream from an otherwise-successful agent (with one loud classification, no skip/retry), or the rule is amended to state that only a dead/crashed agent is refused and a silent-success is detected by the next layer — with a RED-first guard pinning whichever verdict is chosen. This is a separate change: #1808 only attaches stdin and leaves the #1747 classification byte-identical.
- **Signature:** silent-success-agent-green-despite-1747
