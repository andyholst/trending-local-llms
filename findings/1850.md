# Findings

## The dispatch's "no renderer change" constraint conflicts with "the next render keeps it"

- **Evidence:** `trending_card_section()` in `scripts/update_trending.py:1784-1790` hard-codes the "Trending for your card" intro. I added the bridge sentence to `README.md` alone and ran the real `make render-readme`: the sentence was gone (grep count 1 -> 0) and README returned byte-identical to base. No prose-preservation mechanism exists in the renderer. With the same sentence added to the generator's string literal and README regenerated, two consecutive renders are idempotent and the README diff is exactly one paragraph.
- **Why:** a README-only edit would pass review text but be silently deleted by the next sync, so the stated done criterion would not hold. Only a prose string literal changed; no renderer logic, data, schema, table shape or behavior was touched.
- **Done when:** a reviewer confirms the one-literal template change is acceptable under rule 3c, or the owner rules that the intro should become a preserved hand-written block with a dedicated mechanism — a larger change that would need its own issue.

## The AGENTS.md guidance still calls this prose hand-editable

- **Evidence:** the finding's phrasing "README prose only so the next render-readme keeps it" implies hand-authored README prose survives renders. It does not for this section, because the whole section is generated from the template string.
- **Why:** a future docs lane that trusts that phrasing will add prose to README.md alone, and the next sync will silently delete it, recreating the same reader confusion with no commit that ever shows the regression.
- **Done when:** the planner corrects the guidance so future doc fixes know to change `trending_card_section()`'s string literal, not just README.md.
