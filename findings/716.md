## The Renovate App is not installed by this change

- **Signature:** renovate-app-install-owner-action
- **Evidence:** at base `origin/master` `3dfaa97b4259b0c9d4bf16d1f9669ecc679d35f7` the tree had no `renovate.json5` and no Renovate workflow. A config file configures the App; it cannot install it. Installing a GitHub App is an owner repository-settings act, outside this lane's remit (rule 6v).
- **Why:** a merged config with no App installed produces no bump PRs, so #716's auto-bump intent stays inert while a reader assumes the robot is running.
- **Done when:** the owner installs/enables the Renovate App on `andyholst/trending-local-llms`, and an app-side weekly run opens a small guard-green bump PR.

## Tool images pinned in the Makefile are outside this config's reach

- **Signature:** renovate-tool-image-pins-out-of-scope
- **Evidence:** `renovate.json5` enables the `github-actions` and `dockerfile` managers only; the planner ruling for #716 names exactly Action SHAs and Dockerfile base-image versions. Pinned tool images (gitleaks/trivy/grype/syft refs) are named in `Makefile`, which neither manager reads.
- **Why:** claiming those bumps here would be false — the guard cannot prove a bump the config never requests, and widening managers would leave the PR single-purpose rule (#690).
- **Done when:** if tool-image bumps are wanted, they are filed and dispatched as their own slice with a guard that reads the Makefile pins.
