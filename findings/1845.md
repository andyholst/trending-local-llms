# Findings

## The validate job's 30-minute ceiling cancelled a run whose unit suite had already passed

- **Evidence:** PR #1837's qa-validate run `46049222481` ended with `validate` `conclusion=cancelled` at exactly 30 minutes while its unit suite reported `PASSED 124 | FAILED 0` and the guard, closure and live-smoke jobs were green. `.github/workflows/qa-validate.yml:131` declared `timeout-minutes: 30` on the `validate` job; no other job in the workflow carries that value.
- **Why:** a job-level timeout is a hard ceiling on the whole job, so a suite that would otherwise go green is reported as cancelled and the PR cannot auto-merge. The failure is a budget problem, not a test failure; treating it as a flaky test would send the next reader to the wrong seam.
- **Done when:** the shipped `validate` job declares `timeout-minutes: 45`, a guard in `tests/test_workflow_guards.py` pins that value against the shipped YAML (RED at 30, GREEN at 45), and no trigger, schedule, other job timeout, data file, README or schema is changed by the landing.
