# Proposal: merge-tree-index-race-verdict-1822

Issue: #1822

## Why

The `OpenSpec index on the merge tree (issue #1239)` step in `qa-validate` merges
`origin/master` into the PR head and treats any conflict as a hard failure.
`OPENSPEC.md` is generated by `make openspec-index` and every change edits it, so when
master advances mid-`validate` the two sides conflict on that generated file even
though neither author hand-edited it. Measured four times in one cycle (runs
46007342195 / 46012133076 / 46016005004 / 46019681168): a green head failed at the
merge-tree step immediately after a fetched master advance, auto-merge reported
ci-unverified, and every other open PR had to rebase.

## What Changes

- Add the pure seam `scripts/merge_tree_index.py::classify`, reached only through
  `make merge-tree-index-classify` (host `_` recipe + docker wrapper via
  `python-env-image`). It returns `GENERATED_ADVANCE` only when every unmerged path is
  `OPENSPEC.md` and `git merge-base HEAD origin/master` differs from
  `git rev-parse origin/master`; otherwise `REAL_CONFLICT`.
- Extend the merge-tree step additively: capture the unmerged paths BEFORE aborting,
  classify, and on `GENERATED_ADVANCE` do ONE bounded fresh-master retry that
  regenerates the generated index with its OWNING command (`make openspec-index`,
  staged with `git add OPENSPEC.md`) and then runs the UNCHANGED
  `make openspec-index-check` on the merged tree. Emit a distinct
  `[merge-tree-index] MASTER-ADVANCE-RETRY` verdict on success.
- Extend `tests/test_openspec_merge_tree_check.py` with RED-first guards that drive
  the real classifier through the real make target and source-pin every preserved
  #1239 clause.
- Register the target and script in `ARCHITECTURE.md` and regenerate its §10 block.

## Impact

No data format, contract, image, data store, README, cron or Actions schedule change.
`make openspec-index-check` still runs on the merged tree for BOTH verdicts; the
clean-merge stale-index detection, the PR-head `make openspec-check` gate, the
`--check` tolerance and every keeper backstop are byte-unchanged. A genuine source
conflict keeps the exact original `[merge-tree-index] MERGE CONFLICT` + `exit 1`.
`AGENTS.md` is NOT edited by this headless lane; the two approved rule-3c additions
are owed to the owner and declared on issue #1822.
