# Proposal: openspec-invalid-change-repair

Issue: #962 — "The OpenSpec keeper names no repairer for an INVALID ACTIVE CHANGE"
PR: #1086

## Why

`make openspec-check` is the merge gate, and qa-validate gives it exactly one event-driven
keeper: the `index-repair` job runs `make openspec-index-repair`, whose verdict seam
`scripts/openspec_index_repair.py` can answer only `DRIFT=none|index-only`. That seam sees the
generated index; it cannot see the OTHER way the same gate goes red — an ACTIVE change that is
structurally incomplete.

Measured (run 43610043055, push `aec1410`): an active change was shipped as a bare
`openspec/changes/<name>/proposal.md` with no `specs/<capability>/spec.md` and no `tasks.md`.
`openspec validate --changes` failed it, `make openspec-check` went red on every open PR, and the
index keeper answered `DRIFT=none` — the red was not index staleness, so nothing landed and no
named repairer existed. Auto-merge stayed blocked repo-wide until an unrelated keeper PR arrived.

The shape is not hypothetical: rule 6f requires proposal + spec + tasks for every change, and a
change can reach `master` that way whenever a merge carries the scaffold without its body (a
half-landed implement run, a rebase that dropped files). The keeper that already watches this gate
must be able to tell the two shapes apart and repair the one it can honestly repair.

## What Changes

- `scripts/openspec_invalid_change_repair.py` (new): the structural classifier and the repairer.
  `--check` fails (exit 1) when an ACTIVE change lacks `proposal.md`, a
  `specs/<capability>/spec.md` or a `tasks.md`, naming each offender and the exact remedy;
  `--classify-and-archive` lands the honest repair — move the invalid change to
  `openspec/changes/archive/<UTC-date>-<name>/` (the existing archive convention), stamp
  `Binding-exempt: invalid active change repaired by keeper (<run id>)` on the archived proposal
  (the #952 exemption shape), and regenerate the index — it never writes spec or task content it
  did not find; exit 2 loudly when the tree cannot be read; `--print-pr-body` composes the keeper
  body with no closing keyword.
- `scripts/openspec_index_repair.py`: the ONE verdict seam now classifies three shapes —
  `DRIFT=none|index-only|invalid-change` — and an invalid change outranks an index rewrite, naming
  the change and the remedy so the index keeper refuses to launder it as a stale row.
- `scripts/master_alarm.py`: the keeper registry gains the shape table (`index-drift` and
  `invalid-change` for `openspec-check`) and `verdict()` prints the named repairer beside every
  keeper gate of a red push-to-master run, so the alarm routes the shape instead of only notifying.
- `Makefile`: `openspec-invalid-change-check` (bundled as a prerequisite of `make openspec-check`,
  like `openspec-backlog-check` / `openspec-binding-check`), `openspec-invalid-change-repair` and
  `openspec-invalid-change-repair-pr-body`.
- `.github/workflows/qa-validate.yml`: `invalid-change-repair`, the sibling keeper of
  `index-repair` for this shape — `if: failure()` on a push to `master` only, the script's verdict
  decides, only the archive move plus `OPENSPEC.md` may land, keeper dedup honours only a
  MERGEABLE open keeper (#960), never merges, never pushes `master`.
- `tests/test_openspec_invalid_change_repair.py` (new suite) drives the real scripts against
  planted fixture trees; `tests/test_master_alarm.py` and `tests/test_workflows.py` gain the
  additive rows for the new shape and job.
- `ARCHITECTURE.md`: the target rows, the job row and the script row (rule 6h), with §10
  regenerated by `make architecture-refresh`.

## Impact

- `make openspec-check` gains a deterministic Python half that names the invalid change and its
  remedy, in the checkout and in CI, before the container CLI runs.
- A red push-to-master `openspec-check` caused by an invalid active change gets a named repairer
  that lands a keeper PR in that same run, instead of waiting for the Wednesday keeper.
- No data, contract, README or ingest behaviour changes; no existing gate is weakened.

## Not covered

- **AGENTS.md §6q's sentence about the registry** (it names two repairers for `openspec-check`;
  after this change there are three). AGENTS.md is a protected rulebook file a headless leg cannot
  write (rule 3c), so the row is declared as an owed row in `findings.md` and filed as its own
  `tech-debt` issue — the row itself lands in an attended change with the owner's sign-off.
- Retiring `make openspec-archive` (the CLI move) in favour of this seam — the CLI stays the
  human-facing archive path; this seam repairs what a merged tree actually shipped.
- Completing an invalid change by writing the missing spec/tasks: fabricating content is refused
  by rule 2 and out of scope here — the only honest repair of a change nobody wrote is to archive
  it and say so.
