# Change: model-footprint-copy-traceability

**Issue:** #934

## Why

`data/models.json` carries model-level footprint fields (`weight_gb`,
`context_tokens`, `system_ram_min`, `storage_offload`, `engine_min_version`)
copied onto the catalog row — the card-fit tables read them. A measurement-side
copy is readback-checked against the cited post (issue #788/#789), but the
MODEL-level copy is never cross-checked against its own model's measurement
rows or its raw captures: the issue measured 72 model-level fields matching no
measurement row, silently divergent from `data/measurements.json`. An
uncross-checked copy is the #789 disease wearing the catalog's clothes.

## What Changes

- `scripts/validate.py` gains ONE shared capture pool for a model — its own
  measurement rows plus the row-level footprint values captured for that model
  in `data/raw/*.json` — and ONE matcher (`_footprint_copy_supported`:
  normalized containment, figure-token intersection, and K/M expansion so
  `200000` matches `200K`).
- New validator check `check_model_footprint_copy` (stage `data`, wired via
  the existing `--only data,…` lists): a model-level HARD footprint value
  (`weight_gb`, `context_tokens`, `system_ram_min`, `storage_offload`) that
  matches no measurement row AND no capture of the same model FAILS;
  `engine_min_version` stays report-only (the #789 split precedent).
- The shipped store is reconciled: values the captures DO state pass unchanged;
  `200000`/`200K` passes through the matcher improvement; `qwen3-14b`
  `context_tokens 30k` is reconciled to the exact captured `30720`; and the
  fourteen values no capture states — `qwen3-next-80b-a3b` `weight_gb
  48GB (80B-A3B file)`, `kolibri-1` `weight_gb 47.5GB (Q4_K_M)`, `gemma-3-4b`
  `system_ram_min 6GB`, `glm-5.3-flash`, `qwen3-30b-a3b`, `qwen3-4b`,
  `qwen2.5-1.5b-instruct`, `gemma-3-4b` copies — carry the canonical `(est)`
  marker (rule 2), never a deletion.
- `AGENTS.md` §4 gains the model-level copy sentence (rule 3c, attended run).

## Impact

- `scripts/validate.py` (helpers + check + stage registration)
- `data/models.json` (three `(est)` appends — additive, rule 3b)
- `README.md` (regenerated by the render step, not hand-edited)
- `tests/test_model_footprint_copy.py` (new; planted-divergence proof)
- `AGENTS.md` §4 (one sentence)

## Not covered

- Re-searching for the three `(est)` values' true figures (a data-gap, not this
  change).
- Marking `engine_min_version` prose copies (report-only by the #789 precedent;
  gating them was explicitly refused).
